MSL چیست و چرا با probe سنجیده می‌شود؟

هر اپلت روی UICC یک Minimum Security Level دارد که هنگام نصب در پارامترهای INSTALL تثبیت می‌شود (ETSI TS 102 226، بند 8.2.1.3.2). وقتی یک بستهٔ امن OTA برای TAR آن اپلت می‌رسد، کارت سطح امنیتی بسته (اوکتت اول SPI) را با MSL مقایسه می‌کند و اگر کمتر بود، قبل از بررسی MAC و کانتر، آن را رد می‌کند.

هیچ دستوری MSL را از کارت نمی‌خواند — MSL از بیرون «نوشتنی» است، نه «خواندنی». پس تنها راه فهمیدنش، رفتار کارت در برابر بسته‌های با سطوح مختلف است. این کار همان probe است.

MSL سه محور دارد که هر کدام جدا بررسی می‌شوند: یکپارچگی (none / RC / CC / DS)، رمزنگاری (off / on)، کانتر (no-counter / no-check / higher / one-higher). بایت 0x12 یعنی «CC، بدون ciphering، counter-higher».

آماده‌سازی در UL (یک‌بار)

  1. کلاس‌ها در پوشهٔ خروجی UL مستقرند: C:\Users\user\OneDrive\Documents\TAR\Clases
  2. در UL: Tools → Options → Java → Class Path روی همان پوشه باشد (ست شده).
  3. اگر سورس را تازه ساخته‌ای، UL را ببند و باز کن تا کلاس‌های جدید لود شوند.
اگر موقع Compile در UL خطای cannot find symbol: MslCore دیدی، یعنی Class Path خالی است — چون این پروژه چندفایلی است و اسکریپت به کلاس‌های lib/ ارجاع می‌دهد.

کار ۱ — discover امن / فقط خواندنی

با این شروع کن. چیزی نصب یا حذف نمی‌کند.

  1. اسکریپت MslScript را اجرا کن — دیالوگ می‌آید. تا تأیید نکنی هیچ بایتی به کارت نمی‌رود، حتی reset.
  2. تب Job: گزینهٔ discover؛ برچسب کارت را بده (در گزارش می‌آید).
  3. تب OTA key set: مقادیر کارت را وارد کن (جدول مرجع فیلدها را ببین). مهم: KID = کلید واقعی، KIc = خالی وقتی برابرند.
  4. تب Probing: budget = 16 و تیک «Card discards below-MSL packets silently» را بزن (برای کارت MCI لازم است).
  5. تب Report: یک پوشه با دکمهٔ ... انتخاب کن (یا تیک گزارش را بردار).
  6. تب Run: تیک «این مقادیر با سیم داخل ریدر می‌خوانند» → Start run.
نتیجهٔ مورد انتظار برای USIM (B00011): MSL: 12 (cryptographic checksum, no ciphering, counter must be higher) — confirmed

بقیهٔ اپلت‌های محافظت‌شده را هم همین‌طور بزن (هر بار Start counter را کمی بالاتر بگذار): ISIM B00020، HPSIM B00021، RFM B00010، EAP B00022.

کار ۲ — verify امن

وقتی MSL را می‌دانی و می‌خواهی اثباتش کنی:

  1. تب Job: verify.
  2. تب Probing: سه محور MSL ادعایی را از دراپ‌داون‌ها انتخاب کن (برای 0x12: Integrity=CRYPTOGRAPHIC_CHECKSUM، Ciphering=OFF، Counter=PROCESS_IF_HIGHER). تیک silent-drop را هم بزن.
  3. بقیه مثل discover.

PASS یعنی کارت دقیقاً همان MSL را اجبار می‌کند. FAIL یعنی کارت کمتر یا بیشتر از ادعا اعمال می‌کند — و «کمتر» همان چیزی است که باید نگرانش بود.

کار ۳ — install کارت را تغییر می‌دهد

این کار اپلت نصب می‌کند و برگشت‌ناپذیر است. فقط وقتی لازم است که بخواهی یک MSL جدید ست کنی. MSL را نمی‌شود در جا عوض کرد؛ باید instance را حذف و دوباره نصب کرد.
  1. تب‌های GlobalPlatform / Applet / Minimum Security Level را پر کن.
  2. قالب پارامتر را انتخاب کن: UICC (EA{80}) یا SIM (EF{CA}). برای این کارت‌های UICC، پیش‌فرض UICC درست است.
  3. پیش‌نمایش بایت‌به‌بایت پارامترها را قبل از Start بخوان — چون هیچ دستوری بعداً آن را نمی‌خواند که اشتباه را بگیرد.
  4. در تب Run، تیک دوم (پذیرش نصب) هم لازم است.

خواندن نتیجه

  • بلوک حکم در لاگ و در گزارش: PASS، FAIL، UNCONFIRMED، یا UNKNOWN.
  • جدول پروب‌ها: هر بسته با SPI1، امنیت اعمال‌شده، و نتیجه (ACCEPTED / BELOW_MSL / INCONCLUSIVE) و کد PoR.
  • گزارش HTML + CSV در پوشهٔ انتخابی، با نام شامل برچسب کارت و زمان.

در خط ماشین‌خوان: MSL-RESULT|<card>|<TAR>|DISCOVER|PASS|MSL 12

نکات امنیتی و صداقت

  • کلید در هیچ فایلی نوشته نمی‌شود و در گزارش نمی‌آید — تست خودکار این را تضمین می‌کند.
  • discover کانتر OTA کارت را جلو می‌برد (اجتناب‌ناپذیر، بی‌ضرر).
  • این کارت کلید واقعی لازم دارد: بدون MAC معتبر هیچ PoR نمی‌دهد — یک سخت‌سازی خوب که نمی‌گذارد کارت بدون کلید به «اوراکل MSL» تبدیل شود.
  • قبل از Start هیچ چیزی ارسال نشده؛ Cancel یعنی هیچ بایتی نرفته.
