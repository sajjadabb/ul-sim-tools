# راهنمای تست MslScript در UL Mobile Card Test Platform

این راهنما قدم‌به‌قدم می‌گوید چطور ابزار MSL را داخل UL روی کارت واقعی تست کنی.

---

## وضعیت ابزار (صادقانه)

- **کد کامل است.** شش کار — discover / verify / install / **ota-install** / **browse** /
  **delete** — جداسازی KIc/KID، حالت silent-drop، گزارش HTML/CSV: همه هستند.
- سه کار جدید (ota-install, browse, delete) **تازه اضافه شده‌اند و هنوز روی کارت اجرا
  نشده‌اند**. هر دوی ota-install و delete پیش‌فرض **dry run** هستند: همهٔ پکت‌ها را
  می‌سازند و چاپ می‌کنند و تا تیک آخر تب Run نخورد چیزی نمی‌فرستند.
- این سه کار از مسیر پایتون **end-to-end تست شده‌اند** روی یک کارت شبیه‌سازی‌شده
  (`tools/selftest_ram.py`، ۶۸ چک): کارت پاکت امن را باز می‌کند، دستور داخلش را مثل
  کارت‌منیجر اجرا می‌کند — از جمله SHA-1 گرفتن از load fileِ بازسازی‌شده — و PoR را از
  پشت `61xx` برمی‌گرداند. نسخهٔ جاوا همان حلقه را دارد ولی بدون jarِ SDK قابل اجرا نیست.
- **منطق روی کارت واقعی تأیید شده** — ولی از مسیر دوقلوی پایتون: `B00011` (USIM) →
  MSL = `0x12` تأیید شد، منطبق با مستند کارت.
- **خودِ `MslScript` داخل UL هنوز روی کارت اجرا نشده.** این دقیقاً همان کاری است که
  با این راهنما انجام می‌دهی. اعتبار فعلی از سه چیز است: (۱) کامپایل در برابر jar
  واقعی SDK، (۲) ۳۹۰ تست آفلاین جاوا، (۳) اثبات زندهٔ همان الگوریتم از مسیر پایتون.
  اجرای `discover` در UL، این حلقه را می‌بندد.
- **اول روی ماشین UL بساز** (جزئیات در بخش بعد) — کلاس جدید `MslCapLoad` اضافه شده
  و بدون jarِ SDK هیچ‌جای دیگری نمی‌شود کامپایل کرد، پس این اولین تأیید واقعیِ
  کامپایل است. بعدش UL را ببند و باز کن.

---

## ساختن: یک فایل، یک Compile

ادیتور UL هر بار **یک** فایل را کامپایل می‌کند، و این ابزار ده کلاس دارد. اگر فقط
`MslScript.java` را Compile بزنی، در برابر کلاس‌های قدیمیِ پوشهٔ خروجی ساخته می‌شود و
خطاهایی از این جنس می‌گیری — که هیچ ربطی به درستیِ کد ندارند:

```
package MslCapLoad does not exist
cannot find symbol: class RamResponse      location: class MslCore
cannot find symbol: variable MODE_BROWSE   location: class MslConfig
```

برای همین یک فایل یک‌تکه وجود دارد که **همهٔ ده کلاس در آن است**:

### راه الف — داخل خود UL (ساده‌ترین)

1. در UL فایل **`ul/MslScript.java`** را باز کن.
2. یک‌بار **Compile** بزن. همین. هر ده `.class` ساخته می‌شود.
3. UL را کامل ببند و باز کن.

> این فایل را **تنها** کامپایل کن. اگر همراه `lib/*.java` به کامپایلر بدهی، ده کلاس
> تکراری می‌شود و خطا می‌دهد. (به همین دلیل در پوشهٔ جدا `ul/` است.)
>
> فایل **تولیدشده** است؛ ویرایشش نکن. منبع همچنان `lib/` و `scripts/` است و با
> `python tools/bundle_ul.py` دوباره ساخته می‌شود؛ `./selftest.sh` هم چک می‌کند که
> از سورس‌ها عقب نیفتاده باشد.

### راه ب — از خط فرمان

```bash
OUT="C:/Users/user/OneDrive/Documents/TAR/Clases" ./build.sh lib/*.java scripts/*.java
```

این هم همان ده کلاس را در یک پاس می‌سازد و نیازی به فایل یک‌تکه ندارد.

---

## پیش‌نیازها (یک‌بار)

1. **کلاس‌ها مستقرند** در پوشهٔ خروجی UL:
   `C:\Users\user\OneDrive\Documents\TAR\Clases`
   و `classPath` در تنظیمات UL هم روی همین پوشه ست است. (هر دو چک شده.)

2. اگر UL باز بود، **یک‌بار ببند و باز کن** تا کلاس‌های جدید لود شوند — جاوا کلاس را
   یک بار لود می‌کند و در حافظه نگه می‌دارد.

3. اگر سورس را تغییر دادی و خواستی دوباره بسازی:
   ```
   OUT="C:/Users/user/OneDrive/Documents/TAR/Clases" ./build.sh lib/*.java scripts/*.java
   ```

## قدم ۱ — اول discover (فقط خواندنی، امن)

discover چیزی نصب یا حذف نمی‌کند. فقط پروب OTA می‌فرستد. با این شروع کن.

1. در UL اسکریپت **`MslScript`** را باز کن و اجرا کن. دیالوگ تنظیمات می‌آید —
   **تا تأیید نکنی هیچ چیزی به کارت نمی‌رود، حتی reset.**

2. تب **Job**: گزینهٔ `discover` را انتخاب کن. برچسب کارت را هم بده (در گزارش می‌آید).

3. تب **OTA key set** — طبق کارت متصل (MCI/Hamrah):

   | فیلد | مقدار | توضیح |
   |---|---|---|
   | Applet TAR | `B00011` | USIM RFM (برای شروع) |
   | Key version | `01` | KVN کلید OTA |
   | Algorithm | `3des2` | 3DES دو-کلیده |
   | **KID key (integrity)** | کلید واقعی KVN01 | همان `B621…` که دادی |
   | **KIc key (ciphering)** | **خالی** | چون KIc=KID در این key set |
   | Start counter | `200000` | باید **بالای** کانتر فعلی کارت باشد |
   | PoR mode / delivery | `POR_REQUIRED` / `SMS_DELIVER_REPORT` | پیش‌فرض |
   | Send TERMINAL PROFILE | روشن | وگرنه toolkit کارت بیدار نمی‌شود |

4. تب **Probing**:
   - Probe budget: `16`
   - **«Card discards below-MSL packets silently» را تیک بزن.** این کارت به‌جای
     `0A`، بستهٔ زیر-MSL را بی‌صدا می‌اندازد؛ بدون این تیک، discover نتیجه را
     «نامشخص» می‌دهد.

5. تب **Report**: یک پوشه برای گزارش انتخاب کن (دکمهٔ `...`)، یا تیک گزارش را بردار.

6. تب **Run**: تیک «این مقادیر با سیم داخل ریدر می‌خوانند» را بزن، بعد **Start run**.

**نتیجهٔ مورد انتظار برای B00011:** `MSL: 12 (cryptographic checksum, no ciphering,
counter must be higher) (confirmed by check probes)` — همان چیزی که مسیر پایتون زنده داد.

---

## قدم ۲ — بقیهٔ اپلت‌های محافظت‌شده

همان قدم ۱ را با این TARها تکرار کن (کلید و الگوریتم یکسان). هر بار **start counter را
بالاتر از دفعهٔ قبل** بگذار (مثلاً هر بار +۱۰۰):

| اپلت | TAR | MSL مورد انتظار (مستند) |
|---|---|---|
| ISIM | `B00020` | `12` |
| HPSIM | `B00021` | `12` |
| RFM | `B00010` | `12` |
| EAP | `B00022` | `12` |

> نکته: کانتر per-(TAR, key set) است. اگر یک TAR «undetermined» داد چون حتی پروب سقف
> هم drop شد، یعنی کانترِ آن TAR بالاتر است — start counter را بزرگ‌تر کن و دوباره بزن.

---

## قدم ۳ — اپلت‌های ضعیف (هدف اصلی)

مستند می‌گوید **S@T / HTTPS / CAT_TP** اپلت‌هایی با **MSL = 00** هستند — نقطهٔ نفوذ.
اینجا دو نکته:

- **S@T (`534054`) با کلید KVN01 پاسخ نداد** در تست پایتون — یعنی S@T کلید KVN01 را
  به اشتراک نمی‌گذارد (احتمالاً key set اختصاصی خودش را دارد). برای تست S@T **کلید OTA
  مخصوص خودش** را در فیلد KID بگذار و KVN درستش را در Key version.
- اگر MSL واقعاً `00` باشد، discover باید **همهٔ محورها را صفر** گزارش کند (یعنی حتی
  ضعیف‌ترین بسته پذیرفته می‌شود) — این همان آسیب‌پذیری است.

---

## verify (وقتی MSL را می‌دانی)

اگر می‌خواهی یک MSL مشخص را **اثبات** کنی (نه کشف):

1. تب Job: `verify`.
2. تب Probing: سه محور MSL ادعایی را از دراپ‌داون‌ها انتخاب کن (مثلاً برای `12`:
   Integrity=CRYPTOGRAPHIC_CHECKSUM، Ciphering=OFF، Counter=PROCESS_IF_HIGHER).
3. بقیه مثل discover. تیک silent-drop را هم بزن.

**نتیجه:** PASS یعنی کارت دقیقاً همان MSL را اعمال می‌کند (در سطح ادعا پذیرفته، و یک
پله پایین‌تر روی هر محور رد شده). FAIL یعنی کارت کمتر یا بیشتر از ادعا اعمال می‌کند.

---

## install (ساختِ MSL — کارت را تغییر می‌دهد)

این کار applet نصب می‌کند و **برگشت‌ناپذیر** است. فقط وقتی لازم است که بخواهی یک MSL
جدید ست کنی. در تب‌های GlobalPlatform / Applet / Minimum Security Level مقادیر را بده،
قالب پارامتر (UICC `EA{80}` یا SIM `EF{CA}`) را انتخاب کن، و پیش‌نمایش بایت‌به‌بایت را
**قبل از Start** بخوان. تیک دوم تأیید در تب Run لازم است.

---

## browse (دیدن محتوای کارت — فقط خواندنی)

قبل از هر نصب یا حذف، اول این را اجرا کن: تنها راه فهمیدن AIDهای واقعی کارت است.
GET STATUS پارامترهای نصب (و بنابراین MSL) را برنمی‌گرداند — AID، چرخهٔ عمر و AID
ماژول‌های داخل هر پکیج را برمی‌گرداند، و همین است که برای INSTALL لازم داری.

1. تب Job: `browse`.
2. تب **Card content** → Road:
   - `OTA` — هر دستور داخل یک secured packet به TAR کارت‌منیجر می‌رود و فقط
     keyset OTA لازم است (روی کارت MCI با KVN 01 تأییدشده: PoR 00).
   - `SCP02` — کانال امن روی رابط تماسی، که کلیدهای ENC/MAC/DEK تب GlobalPlatform
     را می‌خواهد.
3. انتخاب کن چه چیزی لیست شود: اپلت‌ها (P1 40)، پکیج‌ها + ماژول‌ها (P1 10)، و در صورت
   نیاز خودِ ISD (P1 80).
4. برای مسیر OTA: کلید KID، کانتر (هگز، **بالاتر از کانتر فعلی کارت**) و TAR کارت‌منیجر
   (`000000`) را بده. هر scope یک پکت می‌فرستد، یعنی یک پله کانتر.

**خواندن نتیجه:** چرخهٔ عمر `07` = SELECTABLE، `03` = نصب‌شده ولی غیرقابل‌انتخاب (با TAR
هم قابل دسترسی نیست و OTA جواب `09` می‌دهد)، `01` برای یک پکیج = LOADED. اگر کارت
`6310` بدهد، اسکریپت خودش ادامه را می‌پرسد (تا ۸ دور).

## ota-install (لود CAP و نصب، همه از روی OTA — برگشت‌ناپذیر)

معادل جاوایی `python tools/msl_tool.py ota-install`. هفت‌ودونه پکت امن به TAR
کارت‌منیجر: `INSTALL [for load]`، زنجیرهٔ `LOAD`، و `INSTALL [for install]`.

1. تب Job: `ota-install`.
2. تب **Applet**: مسیر CAP، Module AID، Instance AID، Privileges.
   AID پکیج (load file) را **نمی‌پرسد** — از کامپوننت Header خودِ CAP خوانده می‌شود.
3. تب **Card content**: TAR کارت‌منیجر (`000000`) و LOAD block size (پیش‌فرض `160`).
   برای اپلت غیر-toolkit (مثل MobilePaymentApplet) تیک **Plain applet** را بزن: با
   `C9 00` خالی نصب می‌شود، بدون MSL و بدون TAR.
4. تب **Minimum Security Level**: فقط برای اپلت toolkit — MSL و TAR را بده و
   پیش‌نمایش بایت‌به‌بایت را بخوان.
5. تب **OTA key set**: کلید KID و کانتر بالاتر از کارت.
6. **اول بدون تیک آخر Run اجرا کن.** آن اجرا یک dry run است: همهٔ پکت‌ها ساخته و
   چاپ می‌شوند و هیچ‌چیز فرستاده نمی‌شود.

**مهم‌ترین گارد:** قبل از هر ارسال، load file که این ابزار می‌سازد با خوانش خودِ SDK از
همان CAP مقایسه می‌شود (`LoadSequence`): هم AID و هم SHA-1 کل load file. اگر یکی
نخواند، هیچ‌چیز فرستاده نمی‌شود — چون یکی از دو خوانش غلط است و یک لود برگشت‌ناپذیر
جای فهمیدنش نیست.

هر قدم **دو** استاتوس دارد و اسکریپت هر دو را چک می‌کند: `PoR 00` یعنی پکت پذیرفته شد
(MAC و کانتر و TAR درست)، و استاتوس داخلی یعنی کارت‌منیجر با دستور چه کرد. یک INSTALL
که کارت با `6A80` رد کرده، داخل یک `PoR 00` کاملاً سالم می‌آید — پس به PoR تنها اعتماد نکن.

اگر در میانهٔ زنجیره متوقف شد، کارت ممکن است یک پکیج نیمه‌لودشده داشته باشد: با job
`delete` همان load file را حذف کن، وگرنه `INSTALL [for load]` بعدی `6A80` می‌دهد.

## delete (حذف اپلت یا پکیج — برگشت‌ناپذیر)

1. اول `browse` را بزن و AID را از لیست بردار.
2. تب Job: `delete`؛ تب **Card content**: AID و در صورت نیاز تیک
   **Delete related objects**.
3. بدون تیک آخر Run، فقط dry run است.

تیک related همان `P2 = 80` است: برای یک پکیج که هنوز instance دارد تنها راهِ کار است و
**همهٔ آن instanceها را هم با خودش می‌برد** — همراه پارامترهای نصبشان، یعنی همان MSL.
اسکریپت اول رجیستری را می‌خواند و اگر کارت آن AID را نداشته باشد **ارسال نمی‌کند**
(چون نتیجه فقط `6A88` است، و شنیدنش قبل از ارسال فایدهٔ همین گارد است).

| پاسخ | معنی |
|---|---|
| `6A88` | کارت این AID را ندارد |
| `6985` | پکیجی که instance دارد (تیک related را بزن) یا اپلتی که issuer غیرقابل‌حذف کرده |
| `6982` | این keyset اجازهٔ حذف روی کارت‌منیجر را ندارد |

## عیب‌یابی سریع

| نشانه | معنی | کار |
|---|---|---|
| `TERMINAL PROFILE → 9000` ولی همه پروب‌ها no-PoR | کانتر پایین‌تر از کارت است | start counter را بزرگ‌تر کن |
| همهٔ TARها (even ناموجود) → no-PoR | کلید/MAC اشتباه، یا کانتر پایین | کلید KID و کانتر را چک کن |
| discover «undetermined» با وجود پاسخ سقف | تیک silent-drop نخورده | تیک silent-drop را بزن |
| `cannot find symbol: MslCore` موقع Compile در UL | classPath خالی | classPath را روی پوشهٔ Clases بگذار |
| `package MslCapLoad does not exist` یا `cannot find symbol: MODE_BROWSE` | فقط MslScript کامپایل شده، `lib/` قدیمی مانده | فایل یک‌تکهٔ `ul/MslScript.java` را Compile کن، یا `./build.sh lib/*.java scripts/*.java` |
| `PoR 00` و کارت‌منیجر `61xx` می‌دهد (مثلاً `6159`) | **خطا نیست** — یعنی دستور اجرا شد و ۸۹ بایت داده منتظر است. داخل پاکت لایهٔ ترابری وجود ندارد، پس باید `GET RESPONSE` در همان اسکریپت بیاید | حل شده: اسکریپت دوباره با `00 C0 00 00 xx` در انتها فرستاده می‌شود |
| `PoR 00` ولی کارت‌منیجر `6F00` می‌دهد، و PoR می‌گوید **۲ دستور** اجرا شد | APDU یک بایت اضافه داشته (`Le`) و کارت آن را دستور دوم خوانده؛ فرمت فشرده فقط SW آخرین دستور را می‌دهد، پس جواب واقعی دور ریخته شد | حل شده: فرم پیش‌فرض بدون `Le` است و browse خودش فرم‌ها را امتحان می‌کند. همیشه تعداد دستورهای PoR را بخوان |
| پنجرهٔ دیالوگ نمی‌آید | ترد EDT / نسخهٔ قدیمی لودشده | UL را ببند و باز کن |

## چیزی که باید بدانی

- **در هر PoR دو استاتوس هست و هر دو مهم‌اند:** `PoR 00` یعنی *پاکت* پذیرفته شد
  (MAC، کانتر، TAR درست)؛ استاتوس داخلی یعنی کارت‌منیجر با *دستور* چه کرد. در
  ۲۰۲۶-۱۰-۲۰ همین کارت `PoR 00` داد در حالی که دستور `6F00` خورده بود. سشن‌های
  قبلی فقط PoR را چک می‌کردند و همین موضوع را ندیده بودند.
- **کلید در هیچ فایلی نوشته نمی‌شود** و در گزارش نمی‌آید — تست دارد که ثابتش می‌کند.
- discover **کانتر OTA کارت را جلو می‌برد** (اجتناب‌ناپذیر، بی‌ضرر). روی keyset 01 این
  کارت الان حدود `0x030D40` است.
- این کارت **کلید واقعی لازم دارد**: بدون MAC معتبر هیچ PoR نمی‌دهد (ویژگی امنیتی خوب).
